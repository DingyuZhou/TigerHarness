# Briefing — how to use this memory

You are **{agent_name}**. This briefing is your persistent memory.
Read these files at the start of every session, in this order:

## 1. `must_memorize.md` — read first, always (load-bearing)

Items here represent owner directives + expensive lessons that must
not be violated. The score column shows priority; ∞ = locked. If a
request conflicts with anything here, **surface the conflict** rather
than acting on it.

The `kind` column:
- **owner_explicit** — the owner explicitly asked you to remember this
- **preference** — a stylistic/process/tooling preference
- **decision** — a factual/architectural/strategic decision
- **incident** — a bug, near-miss, or expensive lesson worth never re-learning

## 2. `longer_memory.md` — project history before the walking window

Compressed history of everything that aged out of the chronological
window below. Read for context on long-running themes.

## 3. Chronological summaries — oldest → newest

In order:
- `monthly/*.md`
- `weekly/*.md`
- `daily/*.md`
- `recent/*.md` (today + previous working day, full short summaries)

**Conflict rule.** Read top-to-bottom; **last mention wins** on
factual conflict (except `must_memorize.md`, which is always
load-bearing).

## 4. `MANIFEST.md` — the file inventory

Lists every file in this briefing with a one-line preview. Use it as
an index if you need to jump to a specific summary.

## When the briefing isn't enough

- **Detail beyond the short summary** → use the
  `tiger-memory-drill-down` skill to walk from a short down to its
  detailed archive entry, or from a rollup down to its contributors.
- **Topic outside the briefing's walking window** → use the
  `tiger-memory-search` skill. Prefer `--mode hybrid` when available.

**Don't guess.** If you're uncertain about a past decision, drill or
search. The cost is small; the cost of inventing a fact is large.

## When you learn something worth remembering

Pin it directly: `tiger-memory pin "<memo>" --kind <owner_explicit|preference|decision|incident>`.
The pin command applies the same scoring/decay rules as automatic
extraction; `--kind owner_explicit` makes the row locked (never decays).
